# בקטנה — פשוט לקנות

קוד אמיתי, לא דמה. שלושה חלקים:

- `ingest/` — פייתון שמתחבר לרשתות, מוריד את קובצי ה-XML החוקיים, מפענח ומחשב, וכותב ל-DB.
- `supabase/schema.sql` — כל הטבלאות.
- `web/index.html` — האפליקציה עצמה (עיצוב זכוכית-חלבית/בועתי), קובץ אחד, בלי בנייה (build step).

## למה זה בנוי ככה

הסביבה שבה אני עובד (הטרמינל של קלוד) לא מחוברת לאינטרנט בכלל, אז אני לא
יכול להריץ בעצמי, ברגע זה, קוד שמתחבר לשרתים האמיתיים של הרשתות. לכן:
- כתבתי את כל הלוגיקה האמיתית (login, הורדה, פענוח XML, חישוב) —
  שום מספר בקוד הזה לא מזויף.
- ההרצה הראשונה שמייצרת נתונים אמיתיים תקרה **אצלך**, כשתריץ את זה —
  בין אם מקומית לבדיקה, ובין אם דרך GitHub Actions (שם זה ירוץ אוטומטית
  כל כמה שעות, בלי שתעשה כלום).
- ייתכן שבפורטל של רשת מסוימת יהיה איזשהו שינוי קטן (שם שדה, נתיב) לעומת
  מה שכתבתי — לא בדקתי מול שרת אמיתי. אם ריצה נכשלת, ה-log מדפיס בדיוק
  איפה ולמה, ומתקנים שורה אחת ב-adapter המתאים.

## שלב 1 — Supabase (מסד הנתונים, חינמי, בלי כרטיס אשראי)

1. נרשמים ב-supabase.com עם מייל, יוצרים פרויקט חדש.
2. בתפריט **SQL Editor** מדביקים את כל התוכן של `supabase/schema.sql` ומריצים.
3. בתפריט **Project Settings → API** מעתיקים:
   - `Project URL` — יעד ל-2 מקומות: ה-secret `SUPABASE_URL` ב-GitHub, וגם ב-`web/index.html` (`SUPABASE_URL`).
   - `service_role key` — **סודי**, נכנס רק ל-secret `SUPABASE_SERVICE_KEY` ב-GitHub. לעולם לא בקובץ ה-HTML.
   - `anon public key` — לא סודי, נכנס ל-`SUPABASE_ANON_KEY` בתוך `web/index.html`.

## שלב 2.5 — Supabase Storage לתמונות (פעם אחת)

1. באותו פרויקט: **Storage** בתפריט הצד → **New bucket**.
2. שם: `product-images` (חייב להיות בדיוק זה, כי הקוד מצפה לשם הזה).
3. מפעילים את המתג **Public bucket**. חובה — אחרת התמונות לא ייטענו באתר.
4. **Create bucket**.

## שלב 3 — GitHub (המשיכה האוטומטית של הנתונים, חינמי)

1. יוצרים ריפו חדש, דוחפים אליו את כל התיקייה הזו.
2. ב-**Settings → Secrets and variables → Actions** מוסיפים את שני ה-secrets:
   `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`.
3. בטאב **Actions** — אפשר להריץ ידנית (`workflow_dispatch`) כדי לבדוק מיד,
   בלי לחכות ל-cron. עוקבים אחרי ה-log; זה יגיד בדיוק אם/איפה משהו נופל.

## שלב 3 — האתר עצמו (חינמי, בלי כרטיס)

`web/index.html` הוא קובץ סטטי אחד, בלי build. שתי דרכים לפרסם בחינם:
- **GitHub Pages**: Settings → Pages → מפעילים על אותו ריפו, תיקיית `web/`.
- **Cloudflare Pages / Netlify**: גוררים את התיקייה, בלי חיבור חשבון תשלום.

לפני שמפרסמים — לפתוח את `web/index.html` ולעדכן למעלה:
```js
const SUPABASE_URL = "https://YOUR-PROJECT.supabase.co";
const SUPABASE_ANON_KEY = "...";
```

## בדיקה מקומית של ה-ingest לפני שסומכים על ה-cron

```bash
cd lekanot
pip install -r ingest/requirements.txt
export SUPABASE_URL="..."
export SUPABASE_SERVICE_KEY="..."
python -m ingest.main
```

## מה עוד חסר (בכוונה, לפי סדר עדיפויות שדיברנו עליו)

1. **תמונות** — מחוברות (`ingest/images.py`, ריצה יומית). מקור: Open Food
   Facts לפי ברקוד. כיסוי חלקי - מותגים בינלאומיים כמעט תמיד יש, מותגים
   ישראליים מקומיים בלבד - פחות. מוצר בלי תמונה מציג placeholder נקי,
   לא תמונה מזויפת.
2. **מיקום/מרחק/עלות הגעה** — טבלת `stores` כבר כוללת `lat`/`lng`, אבל
   ה-ingest לא ממלא אותם עדיין (צריך גיאוקוד חד-פעמי לכתובות).
3. **חיפוש סמנטי** — כרגע `ilike` פשוט על שם המוצר. שכבת AI תתווסף כשתרצה,
   בנפרד מהליבה, כדי לא לחייב אותך בכלל עד שתבחר להפעיל אותה.
4. **קישור להזמנה ברשת** — לא התחלנו, כי זה per-chain ולא אחיד.
5. **אימות מחיר בסניף** — הטבלה (`price_confirmations`) כבר קיימת בסכימה,
   ה-UI לדיווח עוד לא מחובר.

זה בכוונה ה-push הגדול הראשון — שלד אמיתי שעובד קצה-לקצה על נתונים אמיתיים,
לא פיצ'רים. השלבים הבאים הם תוספות על גביו, לא בנייה מחדש.
